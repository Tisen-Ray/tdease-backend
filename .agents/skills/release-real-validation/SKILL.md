# Release Real Validation

## Gate

1. Build the Electron installer with `scripts/release/build-desktop.ps1`.
2. Install it into `.scratch/electron-installed` and verify bundled executables and `/ready`.
3. Use `data/system/workflows/wf_test_full.json` unchanged as the workflow document.
4. Use an existing `.raw`, `.mzML`, `.msalign`, or other real data file supplied by the repository/user. Never upload generated bytes.
5. Create a real workspace/sample/run through the public API, execute it, observe at least one execution event/log, then cancel to bound runtime. A run that reaches `failed` during this window fails the gate.
6. Save run id, template path, data path, status, events, logs, and installed-app evidence under `.scratch`.
7. AI provider configuration is optional and informational; missing AI credentials must not block the Electron release gate. When configured, DeepSeek is the default provider.
8. Validate one normal launch without `--user-data-dir`. Confirm `%APPDATA%/TDEase` is the active data root and the canonical system template is returned by the workflow-template API.

Do not count Docker, `/health`, mock API fixtures, synthetic workflows, or unit tests as release validation. AI chat smoke is a separate optional diagnostic and is never a release gate.
